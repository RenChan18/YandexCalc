Этот проект представляет собой веб-сервис для вычисления арифметических выражений на Go.

## Структура проекта
```go
.
├── cmd
│   ├── agent
│   │   └── main.go
│   ├── calc_service
│   │   └── main.go
│   └── orchestrator
│       └── main.go
├── go.mod
├── go.sum
├── internal
│   ├── calculator
│   │   └── calculator.go
│   └── orchestration
│       └── handler.go
├── README.md
└── tests
    └── calculator_test.go
```

- `cmd/orchestrator/main.go`: Запуск сервера оркестратора (принимает выражения, разбивает их на задачи, хранит их состояние и предоставляет API для клиентов и агентов).  

- `cmd/agent/main.go`: Запуск демона агента (постоянно опрашивает сервер для получения задач, выполняет вычисления (с использованием уже существующей логики, где это применимо) и отправляет результат обратно серверу).

- `internal/orchestration/handler.go`: HTTP-обработчики для оркестратора.

- `tests/calculator_test.go`: Тесты для калькулятора.

- **Оркестратор** – HTTP-сервер, принимающий арифметические выражения, формирующий задачи и управляющий их выполнением.
- **Агент** – демон (worker), который постоянно опрашивает оркестратора, получает задачи, выполняет вычисления и отправляет результаты обратно.
- **Calc Service (опционально)** – отдельный HTTP-сервис для непосредственного вычисления выражений.



## Запуск проекта

```bash
go run ./cmd/agent/main.go
go run ./cmd/orchestrator/main.go
```


## Предварительные требования

- Go версии 1.16 или выше.
- Git (для клонирования репозитория).

## Настройка переменных окружения

Перед запуском сервисов установите следующие переменные:

```bash
export TIME_ADDITION_MS=100
export TIME_SUBTRACTION_MS=100
export TIME_MULTIPLICATIONS_MS=150
export TIME_DIVISIONS_MS=150
export COMPUTING_POWER=4
```

- **TIME_*** — задают задержку (в мс) для имитации выполнения соответствующих арифметических операций.
- **COMPUTING_POWER** — определяет количество горутин (параллельных воркеров) в агенте.

## Варианты использования

### 1. Запуск оркестратора (сервер)

Оркестратор принимает запросы для вычислений и распределяет задачи между агентами.

- **Запуск:**

  В одном терминале выполните:

  ```bash
  cd cmd/orchestrator
  go run main.go
  ```

  Сервер будет запущен на порту `8080`.

- **Примеры использования API:**

  - **Добавление выражения (POST /api/v1/calculate):**

    ```bash
    curl --location 'http://localhost:8080/api/v1/calculate' \
    --header 'Content-Type: application/json' \
    --data '{"expression": "2+3*4"}'
    ```

    Ответ:

    ```json
    {"id":1}
    ```

  - **Получение списка выражений (GET /api/v1/expressions):**

    ```bash
    curl --location 'http://localhost:8080/api/v1/expressions'
    ```

  - **Получение конкретного выражения (GET /api/v1/expressions/1):**

    ```bash
    curl --location 'http://localhost:8080/api/v1/expressions/1'
    ```

  - **Эндпоинты для агентов:**
    - **GET /internal/task** – для получения задачи.
    - **POST /internal/task** – для отправки результата вычисления.

### 2. Запуск агента (worker)

Агент запрашивает задачи у оркестратора, выполняет вычисления и отправляет результат.

- **Запуск:**

  Откройте отдельный терминал и выполните:

  ```bash
  cd cmd/agent
  go run main.go
  ```

  Агент использует переменную `COMPUTING_POWER` для определения количества параллельных воркеров.

### 3. Запуск калькулятор-сервиса (опционально)

Этот сервис позволяет напрямую вычислять арифметические выражения через HTTP-запросы.

- **Запуск:**

  Откройте ещё один терминал и выполните:

  ```bash
  cd cmd/calc_service
  go run main.go
  ```

  Сервис запустится на порту `8081`.

- **Пример запроса:**

  ```bash
  curl --location 'http://localhost:8081/calc?expr=2+3*4'
  ```

  Ответ:

  ```
  Result: 14
  ```
Ниже приведён пример использования API с ошибкой и пояснениями, что может пойти не так.

### Пример запуска с ошибкой

#### 1. Отправка невалидного арифметического выражения

Например, если отправить выражение с недопустимым символом:

```bash
curl --location 'http://localhost:8080/api/v1/calculate' \
--header 'Content-Type: application/json' \
--data '{"expression": "2+abc"}'
```

**Ожидаемый ответ:**

```json
invalid expression: invalid character: a
```

В этом случае сервер возвращает код **422 Unprocessable Entity**, так как выражение содержит символы, которые не распознаются калькулятором.

---

#### 2. Получение выражения по несуществующему ID

Если выполнить запрос к несуществующему идентификатору выражения:

```bash
curl --location 'http://localhost:8080/api/v1/expressions/999'
```

**Ожидаемый ответ:**

```text
expression not found
```

Сервер возвращает **404 Not Found**.

---

#### 3. Попытка получить задачу, когда их нет в очереди

Если в системе нет доступных задач для агента, запрос:

```bash
curl --location 'http://localhost:8080/internal/task'
```

**Ожидаемый ответ:**

```text
no task
```

При этом сервер отвечает с кодом **404 Not Found**.


### 4. Тестирование

Запустить тесты для логики вычислений можно следующей командой:

```bash
go test ./tests
```

Или запустить тесты для конкретного пакета:

```bash
go test ./internal/calculator
```

## Дополнительная информация

- **Логирование:** Оркестратор и агент выводят логи в stdout. Рекомендуется мониторить их для отладки и контроля работы.
- **Обработка ошибок:** В данном примере реализована базовая обработка ошибок. Для продакшн-решения стоит добавить более надежную обработку и логирование.
- **Масштабируемость:** Запустите несколько агентов (на разных машинах или в контейнерах), чтобы распределить нагрузку. Все агенты будут обращаться к оркестратору по заданному адресу.
- **Расширяемость:** Проект можно дополнить базой данных для хранения состояния выражений, системой аутентификации, мониторингом и более сложной логикой разбиения задач.
